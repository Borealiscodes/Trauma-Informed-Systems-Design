# **NDH–ZenAI Invariants Mapping (v1.0)**  
### Formal Alignment Between NDH/TISD Governance and ZenAI Enterprise Architecture

## Purpose

This document provides a structured mapping between **NDH/TISD trauma-informed invariants** and **Zühlke’s ZenAI enterprise agentic platform**. It serves as the bridge between conceptual governance (NDH) and practical implementation (ZenAI), completing the initial four-artifact integration cluster.

This mapping supports:

- reference architecture development  
- pilot workflow design  
- governance alignment  
- trauma-informed AI deployment  
- future collaboration decisions  

---

# 1. NDH/TISD Invariants → ZenAI Platform Capabilities

## 1.1 Dignity as a Design Invariant  
**NDH Requirement:**  
Systems must preserve dignity at every interaction point.

**ZenAI Alignment:**  
- Role-based access control  
- Privacy classifications  
- On-prem / private cloud deployment  
- Controlled data flow (three-stage safety system)

**Mapping Insight:**  
ZenAI’s security posture provides the structural boundary; NDH defines the ethical boundary.

---

## 1.2 Predictability as Accessibility  
**NDH Requirement:**  
Predictable steps reduce cognitive load and trauma activation.

**ZenAI Alignment:**  
- Agentic workflows with explicit step sequences  
- Workflow builder for consistent process design  
- Automated timeline generation  
- Standardised integration with existing systems

---

## 1.3 Single-Channel Communication  
**NDH Requirement:**  
Avoid forcing vulnerable individuals to switch channels or repeat their story.

**ZenAI Alignment:**  
- Unified chat interface  
- Centralised agentic workflows  
- Canonical narrative reuse  
- REST API for channel consolidation

---

## 1.4 Holonomy Flattening  
**NDH Requirement:**  
Prevent recursive self-advocacy loops.

**ZenAI Alignment:**  
- Canonical case narrative stored in data pools  
- Agents reuse the same narrative  
- Privacy classifications prevent fragmentation  
- Workflow builder enforces consistency

---

## 1.5 Trauma-Safe Boundaries  
**NDH Requirement:**  
Boundaries must be clear, stable, and non-absorptive.

**ZenAI Alignment:**  
- Secure hosting  
- Provider-agnostic model selection  
- No external model training on sensitive data  
- Access parity with existing systems

---

## 1.6 Non-Linear Development  
**NDH Requirement:**  
Systems evolve emergently without collapsing into “finished/unfinished.”

**ZenAI Alignment:**  
- Modular architecture  
- Configurable agents  
- Easy update and modification  
- Collaborative tailoring
