# NDH–ZenAI Pilot Workflow Specification  
### Version 1.0  
### Operational Blueprint for Trauma-Informed Agentic Workflows

## Purpose

This specification defines the **first operational workflow** for an NDH-governed
pilot running on Zühlke’s ZenAI enterprise agentic platform. It translates the
Reference Architecture Draft into a concrete, testable workflow that demonstrates
how NDH invariants, GBS structures, and ZenAI capabilities interact in practice.

This workflow is intentionally scoped to be small, safe, and non-binding.

---

# 1. Workflow Overview

## Workflow Name  
**Trauma-Informed Intake & Canonical Narrative Formation**

## Workflow Goal  
Capture a user’s story **once**, transform it into a **canonical narrative**, and
route it through a predictable, trauma-safe workflow without requiring repetition,
channel switching, or self-advocacy loops.

## High-Level Flow

```text
User → Intake Agent → Canonical Narrative → NDH Constraints → ZenAI Workflow → Output
```

---

# 2. NDH Governance Requirements Applied

### 2.1 Dignity Invariant  
- No adversarial questioning  
- No forced repetition  
- No ambiguous steps  
- No unexplained transitions

### 2.2 Predictability  
- Workflow steps must be visible and stable  
- No hidden branching  
- No conditional jumps without explanation

### 2.3 Single-Channel Communication  
- All interactions occur through one interface  
- No email, phone, or external system redirection

### 2.4 Holonomy Flattening  
- Detect and prevent loops where the user must re-explain themselves  
- Canonical narrative reused across all agents

### 2.5 Trauma-Safe Boundaries  
- Clear start and end  
- No data absorption beyond defined privacy class  
- No cross-department leakage

---

# 3. GBS Structural Mapping

### 3.1 Manifold  
All possible intake paths (structured, unstructured, partial, fragmented).

### 3.2 Tensor  
Multi-dimensional representation of the user’s narrative, metadata, and context.

### 3.3 Vector  
The actual trajectory the user takes through the workflow.

### 3.4 Scalar  
Misalignment metrics (e.g., confusion, repetition, boundary violations).

### 3.5 Envelope  
Stability bounds ensuring trauma-safe interaction.

### 3.6 Holonomy  
Loop detection:  
- repeated questions  
- repeated narrative requests  
- repeated identity verification

### 3.7 Output  
Canonical narrative + workflow summary + next-step options.

---

# 4. ZenAI Platform Configuration

## 4.1 Agents

### **Intake Agent**
- Collects initial narrative  
- Applies NDH constraints  
- Generates structured + unstructured data pools

### **Narrative Consolidation Agent**
- Converts raw narrative into canonical form  
- Ensures privacy class compliance  
- Prevents fragmentation

### **Workflow Guidance Agent**
- Presents predictable steps  
- Ensures user never repeats information  
- Provides trauma-safe transitions

---

## 4.2 Workflow Steps

```text
Step 1 — Greeting & Boundary Setting  
Step 2 — Narrative Capture  
Step 3 — Canonical Narrative Formation  
Step 4 — NDH Constraint Validation  
Step 5 — Workflow Execution  
Step 6 — Output & Next Steps
```

---

## 4.3 Privacy Classes

- **Class A:** User-provided narrative  
- **Class B:** Derived canonical narrative  
- **Class C:** Workflow metadata  
- **Class D:** System-level logs (non-sensitive)

No cross-class leakage permitted.

---

## 4.4 Role-Based Access

- Intake Agent: A, B  
- Narrative Agent: A, B, C  
- Workflow Agent: B, C  
- Admin: C, D  
- No role has access to all classes.

---

# 5. Trauma-Informed Interaction Rules

- No “Why?” questions  
- No “Explain again” prompts  
- No multi-channel redirection  
- No ambiguous transitions  
- No unbounded silence  
- No conditional branching without explanation  
- No data absorption beyond privacy class  
- No workflow loops
