# ⭐ **2 — Executive Summary (Updated)**

The AI for Good Lab already maintains a **researcher directory** on the Microsoft Research website.  
However:

- it is **not linked** from AI for Good public pages  
- it is **not framed** as a humanitarian access surface  
- it is **not continuity‑safe**  
- it is **not trauma‑informed**  
- it is **not integrated** into Microsoft Support or EDAD routing  
- it is **not indexed** for HRDs or vulnerable communities  

Therefore:

> **OAR‑03 exists, but only as a latent access surface — not an operational one.**

This roadmap update transforms OAR‑03 from **latent** → **functional**.

# ⭐ **3 — Updated Access Layer Remediation (OAR‑03 Revised)**

## **OAR‑03 — Researcher Directory (Existing but Non‑Operational)**

### **Current State (Observed):**
The AI for Good Lab’s researcher directory:

- exists on Microsoft Research  
- lists names, roles, and project affiliations  
- is discoverable only through manual traversal  
- is not linked from AI for Good public pages  
- is not framed as a contact surface  
- is not humanitarian‑accessible  
- is not continuity‑preserving  
- is not trauma‑informed  
- is not integrated into routing geometry  
- is not part of EDAD or Support escalation pathways  

### **Remediation Requirement (Updated):**
Transform the existing directory into an **operational humanitarian access surface** by:

- linking it from AI for Good public pages  
- adding trauma‑informed access notes  
- adding continuity‑preserving guidance  
- adding routing instructions  
- adding humanitarian intake context  
- adding accessibility framing  
- integrating it into Microsoft Support routing  
- integrating it into EDAD routing  
- integrating it into internal escalation protocols  
- adding a “How to Contact the Lab” header  
- adding a “Humanitarian Access Pathway” section  

### **Ethical Justification:**
A latent directory is not an access surface.  
Humanitarian actors require **explicit**, **safe**, **continuity‑preserving** access.

### **Governance Note:**
This satisfies the *existence* of OAR‑03 but not the *function* of OAR‑03.
