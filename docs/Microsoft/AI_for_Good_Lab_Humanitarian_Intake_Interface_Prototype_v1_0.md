# ⭐ **2 — Interface Philosophy**

The interface is designed around four principles:

### **IP‑01 — Trauma‑Informed Design**
Avoid cognitive overload, ambiguity, urgency pressure, and abrupt closure.

### **IP‑02 — Continuity Preservation**
Ensure stable pacing, predictable sequencing, and clear next steps.

### **IP‑03 — Humanitarian Reachability**
Provide explicit access surfaces for HRDs and vulnerable communities.

### **IP‑04 — Routing Integrity**
Ensure submissions reach researcher nodes and avoid routing voids.

# ⭐ **6 — Section 3: Routing Preview**

This section shows the user **how their submission will move through the system**, eliminating ambiguity.

### **RP‑01 — Routing Path**
```
Your submission will follow this path:

Intake Portal → Researcher Nodes → Internal Microsoft Research Routing → Initiative Cluster → Response
```

### **RP‑02 — Researcher Node Visibility**
Show the relevant nodes (not emails):

- Deputy Lab Director  
- Senior Directors  
- Project Leads  

### **RP‑03 — No Routing Void Guarantee**
Explicitly state:

“Your submission will not be routed into the public-layer void.”
